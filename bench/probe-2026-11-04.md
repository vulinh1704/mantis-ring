## What it settles

- **Bake-off gate (p1 and p2):** all five text models pass, so none is dropped.
- **Echoed reasoning (R-d):** for all five, the gateway accepts an assistant message sent back with a `reasoning` field (200, no 400).
  - Only qwen3.8-27b returned its own reasoning text in p1, so the other four were sent a stand-in text.
  - Stripping stays the default. The gateway does not require it.
- **Forced `tool_choice` (R-c):** all five accept it (200, never 400 or 422). On a fresh request (p5), four models honour it: deepseek, glm-5.3, glm-5.3-flash and qwen3.8-27b. minimax-m3.1-flash ignored it and called `read_file`. The loop must keep ending the task itself.
- **Vision `response_format` (strict `json_schema`):** both models accept it (200).
  - qwen3.8-27b returns valid JSON with verdict `cover_up` (target not visible after), using 503 prompt tokens.
  - deepseek-v4.1-flash-1017 hit `length` at 1024 completion tokens, with only 43 of them reasoning. Its JSON was cut off after it began `{"verdict":"cover_up",...`.
  - Keep qwen3.8-27b as the vision model (D-1).
- **glm-5.3 latency (R-e):** p2 took 15.6 s and p4 took 30.6 s. Every other tool-calling step, on any model, took at most 1.3 s. This looks like silent queueing at the gateway.
